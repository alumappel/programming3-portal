# שירות הניהול של הפורטל

לעריכת הפרונט פותחים את תיקיית `website` ב־VS Code ומשתמשים ב־Live Server. אין צורך להפעיל את השירות הזה לצורך שינוי HTML, CSS או JavaScript.

שירות הניהול נשמר בנפרד כדי לאפשר התחברות, טיוטות, העלאות PDF ופרסום עם אימות שרת. כל הנתונים הפרטיים הועברו אל `backend/.local/portal.sqlite`; אין נתונים פרטיים בתיקיית האתר הציבורית.

## הפעלה כשנדרשות פעולות ניהול

נדרש Node.js בגרסה 24 ומעלה. מתיקיית `backend`, הפעילו `./start.ps1` או `npm.cmd start` ופתחו את [העורך המקומי](http://127.0.0.1:4173/admin.html).

בכניסה הראשונה בוחרים בעורך סיסמה באורך 12 תווים לפחות ומקלידים אותה שוב לאישור. לאחר מכן מתחברים עם `Admin` ואותה סיסמה גם בהפעלות הבאות. במסד הנתונים הפרטי נשמר רק גיבוב עם מלח אקראי; הסיסמה עצמה אינה נשמרת בקבצים. עצירה באמצעות Ctrl+C שומרת את התוכן ואת הגדרת הסיסמה. בהפעלה מחדש החיבורים הקודמים מתבטלים ויש להתחבר שוב.

השרת מגיש את אותם קובצי `website` באופן ישיר. אין העתקה, יצירת HTML או שלב build. גם בעריכה שלו שינוי קובץ CSS או HTML דורש רק שמירה ורענון בדפדפן.

## חיבור הפרונט לתוכן שפורסם

ברירת המחדל של Live Server היא קריאת `website/data/content.json`, עם 35 קבוצות וחמשת השלבים שפורסמו. **פרסום הפעילות בעורך מעדכן אוטומטית את הקובץ הזה ואת קובצי ה־PDF שפורסמו.** האתר מתעדכן ברענון או בבדיקת העדכונים התקופתית, בתוך כ־30 שניות. שמירת טיוטה לבדה אינה משנה את האתר הציבורי. אין צורך לבצע ייצוא אחרי פרסום תקין.

אפשרויות נוספות:

- אפשר לערוך את קובץ התוכן ידנית; הפרסום הבא מהעורך יחליף אותו בתוכן שפורסם מהטיוטה. HTML ו־CSS אינם משתנים בפרסום. אם מוצגת אזהרה שהפרסום הצליח אך העדכון ל־Live Server נכשל, הפעילו `npm.cmd run export` בתיקיית `backend` לאחר תיקון התקלה. הפקודה מעתיקה רק תוכן וקובצי PDF שפורסמו.
- לקרוא את התוכן ישירות מהשירות: הגדירו `readFromApi: true` ואת `backendUrl` ב־`website/js/config.js`. בשירות המקומי מקור ברירת המחדל המותר לקריאה הוא `http://127.0.0.1:5500`; אפשר לשנות אותו באמצעות משתנה הסביבה `PUBLIC_ORIGIN`.

בפתיחת האתר על כתובת השירות עצמו, התוכן נקרא אוטומטית מה־API. כניסה וכתיבה בעורך מתבצעות על מקור השירות עצמו, עם חיבור ו־CSRF. אין התחברות מדומה בדפדפן ואין סיסמאות בקוד הציבורי.

## קבצים בעורך

כל העלאת PDF יוצרת ושומרת בטיוטה בלוק הנחיה נפרד, עם קובץ אחד וללא טקסט. בוחרים בבלוק את השלב והקבוצה, עורכים כותרת וסדר ומסמנים לפרסום. קבצים ישנים שטרם שויכו להנחיה מופיעים כבלוקים שאינם מסומנים לפרסום. קבצים שהיו מצורפים להנחיית טקסט נפרדים ממנה תוך שמירת השיוכים והטקסט; שמירת הטיוטה שומרת את ההפרדה.

בעורך ההנחיות מוצגות לפי מועד היצירה, מהחדש לישן, כולל בלוקי קבצים. בממשק הסטודנטים הסדר נקבע לפי **סדר התצוגה** של כל בלוק. מועד היצירה נשמר עם הנחיות חדשות וקובצי PDF חדשים כדי שהסדר בעורך יישמר גם אחרי כניסה חוזרת.

כפתור **מחיקת הקובץ** מסיר מהטיוטה את הקובץ ואת הבלוקים המשויכים לו. שומרים ומפרסמים כדי להחיל את המחיקה באתר הסטודנטים. גרסאות קודמות וקובצי המקור נשמרים לשחזור; המחיקה בעורך אינה מחיקת גיבויים או השמדה פיזית של האחסון.

## בדיקות

```text
npm.cmd run check
npm.cmd test
```

בדיקות הפרונט והפניות הנכסים נמצאות גם הן כאן, כדי להשאיר את תיקיית האתר ללא כלי פיתוח. בדיקות דפדפן מבצעים ידנית לפי [מדריך הבדיקות](../website/TESTING.md), כולל בחירת סיסמה, שמירת טיוטה ופרסום.

## גיבוי

לעותק העריכה שלא נשמר אפשר להשתמש בכפתור בעורך. לגיבוי מלא יש לעצור את השירות ולהעתיק את `backend/.local` למקום פרטי. הוא מכיל גם את קובצי ה־PDF ואת גיבוב סיסמת העורך. לשחזור שמרו תחילה את התיקייה הנוכחית והחזירו את העותק המגובה לפני הפעלה מחדש. אין למחוק את מסד הנתונים כדי לאפס סיסמה: הוא מכיל גם את התוכן.

עותק מלא של מבנה הפרויקט לפני הפישוט נשמר ב־`work/before-vanilla-cleanup-complete-20261021.zip`.

## מתאם Cloudflare

קוד ה־Worker, מתאם מאגר התוכן הפרטי והמיגרציה של D1 נשמרו. קובץ `wrangler.example.toml` מצביע כעת אל `website` ישירות. לפני פריסה יש להגדיר כתובות אמיתיות ב־`website/js/config.js`, כתובות מקורות ב־Wrangler וסודות כניסה ו־GitHub בצד השירות. לשימוש בתוכן חי יש לבחור `readFromApi: true`. אין כרגע חיבור לחשבונות ייצור.
