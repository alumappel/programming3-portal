# האתר והעריכה ב־VS Code

פותחים את `website` ב־VS Code, לוחצים לחיצה ימנית על `index.html` ובוחרים **Open with Live Server**. משנים קובץ, שומרים ורואים את השינוי. אין התקנת חבילות ואין שלב בנייה.

## איפה עורכים

| קובץ | מה עורכים בו |
| --- | --- |
| `index.html` | מבנה וטקסטים קבועים של ממשק הסטודנטים |
| `css/style.css` | צבעים, רקע, כרטיסיות, מרווחים והתאמה למובייל |
| `js/app.js` | בחירת קבוצה, מעבר בין שלבים וטעינת התוכן |
| `data/content.json` | התוכן המקומי, 35 הקבוצות והשלבים שפורסמו |
| `images/` | תמונות ואיורים |
| `admin.html` ו־`css/admin.css` | מבנה ועיצוב העורך |
| `js/config.js` | הגדרות חיבור לשירות, אם נדרש |

Bootstrap נמצא ב־`lib/bootstrap`, והגופן Rubik ב־`fonts`. הקוד הרגיל משתמש ב־HTML, CSS ובמודולים טבעיים של JavaScript שהדפדפן יודע לטעון. אין React, bundler, placeholders או קובצי הפצה שנוצרים בנפרד.

קובצי `js/helpers.js` ו־`js/domain.js` מכילים פעולות משותפות לתוכן, לתאריכים ולתצוגה; בדרך כלל אין צורך לגעת בהם כשעורכים את העיצוב.

## תוכן מקומי ושירות הניהול

הפרונט קורא כברירת מחדל את `data/content.json` ופועל ב־Live Server ללא שרת נוסף. הכותרות הקבועות שאתם עורכים ב־HTML נשארות כפי שכתבתם. שינויי תוכן בקובץ JSON מופיעים ברענון או בבדיקת העדכונים האוטומטית.

שירות ההתחברות, הטיוטות והפרסום נמצא בתיקיית `backend` הנפרדת. מפעילים מתוכה `./start.ps1` או `npm.cmd start` ופותחים את [העורך](http://127.0.0.1:4173/admin.html). בביקור הראשון בוחרים סיסמה; שם המשתמש הוא `Admin`.

שמירת טיוטה משאירה את השינויים בעורך. **פרסום הפעילות מעדכן אוטומטית את `data/content.json` ואת קובצי ה־PDF הציבוריים**, כך שגם האתר ב־Live Server מקבל את העדכון. קובצי העיצוב נשארים לעריכה ישירה ב־VS Code. הוראות השירות והגיבוי נמצאות ב־[backend/README.md](../backend/README.md).

## מניעת מטמון ישן

הוגדר ל־Live Server ולשירות המקומי להגיש קבצים עם `Cache-Control: no-store`. ב־HTML ובייבוא מודולים יש גם פרמטר `?v=`; קוד הסטודנטים, העורך ורכיבי התוכן המשותפים מתעדכנים עם `?v=20261021-file-blocks-2`. בהעלאה לאירוח רגיל מעדכנים את המספר בקישורים לקבצים ששונו; שמות הקבצים עצמם נשארים ברורים וקבועים.

## בדיקה ידנית

ראו [TESTING.md](TESTING.md) לצעדי הבדיקה ומה לעשות במקרה של תקלה. נבדקו בקוד הפניות הנכסים, קריאת תוכן מקומי ופעולות השירות; לא בוצעה שליטת דפדפן לבדיקת תצוגה.

איור עמוד השילוט בבאנר נוצר באמצעות כלי יצירת התמונות המובנה, בפלטה ובסגנון של [מאגר ההשראה שסופק](https://github.com/alumappel/Enrichment-Materials-Website-for-Students). הוא נשמר ב־`images/direction-signpost.png` עם רקע שקוף. פרטי היצירה והפרומפט נשמרו ב־`backend/ASSETS.md`. רישיונות Bootstrap ו־Rubik מצורפים לתיקיות שלהם.
