# בדיקה ידנית עם Live Server

הבדיקות בדפדפן מיועדות לביצוע ידני. לא נעשה שימוש בשליטת דפדפן אוטומטית.

## פתיחה ועריכת HTML

1. פתחו ב־VS Code את תיקיית `website` ובחרו על `index.html` את **Open with Live Server**.
2. שנו טקסט בכותרת או בתחתית `index.html` ושמרו.

צפוי: האתר נפתח ללא הפעלת Node, ללא npm וללא בנייה. השינוי מופיע בדפדפן, והכותרת שערכתם אינה נדרסת על ידי JavaScript במצב המקומי.

אם יש תקלה: בדקו שהתוסף Live Server מותקן ושהכתובת היא `http://127.0.0.1:5500/` ולא `file://`. אם נפתח מסך בחירת תיקיות, עברו ל־`index.html`. אם פתחתם את כל הפרויקט ולא רק את `website`, ודאו שהגדרת `liveServer.settings.root` מצביעה אל `/website`.

## עריכת CSS ותמונות

1. שנו צבע או מרווח ב־`css/style.css` ושמרו.
2. בדקו את רקע המשבצות, צבעי הכרטיסיות ועמוד השילוט בבאנר.
3. החליפו זמנית את תמונת הבאנר בתמונה מקומית אחרת ושמרו את ה־HTML.

צפוי: ה־CSS נטען ישירות, ללא תוצר ביניים. התמונה והרקע מוצגים והדף אינו זקוק לקובצי `dist`. השינוי נשמר גם לאחר רענון רגיל.

אם יש תקלה: בדקו את הנתיב היחסי ב־`href`, ב־`src` או ב־`url(...)`, כולל סיומת הקובץ ואותיות גדולות וקטנות. אין לערוך קובץ Bootstrap הממוזער כדי לשנות מיתוג; השתמשו ב־`css/style.css`. בהפצה רגילה שנו את ערך `?v=` של קובץ שעודכן; ב־Live Server הוגדרה כותרת `no-store`.

## תוכן וקבוצות

1. בחרו קבוצה 1, עברו לקבוצה 35 וחזרו לבחירה ללא קבוצה.
2. פתחו את `data/content.json`, שנו טקסט בהנחיה ושמרו. אין צורך לשנות קוד JavaScript כדי לערוך את התוכן שבקובץ.
3. פתחו שלב זמין ושלב עתידי בהתאם למועדים הקיימים בקובץ.

צפוי: קיימות 35 קבוצות. הנחיות משותפות נשארות והנחיות קבוצתיות מתחלפות. לפני מועד הפתיחה מוצגים שם ומועד בלבד. שינוי JSON נטען ברענון או בבדיקת העדכונים התקופתית, גם אם לא שיניתם את מזהה הגרסה.

אם יש תקלה: בדקו ש־JSON תקין, בלי פסיק עודף או מרכאות חסרות, ושהשיוכים הם למזהי קבוצות ושלבים קיימים. בדקו ב־`js/config.js` שההגדרה `readFromApi` היא `false` לעבודה מקומית ללא שירות. אם שלב נראה נעול בטעות, בדקו את השעה במכשיר ואת מועדו ב־UTC.

## מובייל ומקלדת

בדקו ברוחבי 320, 375, 768 ו־1280 פיקסלים ובהגדלה 200%. עברו בעזרת Tab ובדקו את קישור הדילוג, בורר הקבוצה, כפתורי השלבים וקישורי הקבצים. פתחו טופס בדיקה ונסו לעבור שלב; ביטול האזהרה צריך להשאיר את הטופס פתוח.

צפוי: אין גלילה אופקית של כל העמוד, אין חפיפת טקסט ותמונה, ויש מיקוד ברור. איור עמוד השילוט דקורטיבי ואינו מקבל מיקוד.

אם יש תקלה: תעדו את רוחב החלון, גודל הזום, הדפדפן והפעולה שנכשלה. בדקו את כלל ה־CSS של הרכיב ואת השאילתה המתאימה לרוחב המסך; אין צורך להריץ בנייה מחדש.

## בדיקת עדכון הבאנר והסרת פרטי התצוגה

פתחו את `index.html` עם Live Server ורעננו רגיל. ודאו שבכותרת מופיע עמוד שילוט עם חצים בצבעי האתר ורקע שקוף, שהערת השעון אינה מופיעה לצד השלבים ושאין מספר גרסה בתחתית. עברו בין קבוצות ושלבים כדי לוודא שהתוכן ממשיך להיטען גם לאחר הסרת הרכיבים. בדקו גם ברוחב 320 פיקסלים.

אם יש תקלה: אם התמונה הישנה נשארה, בדקו שכתובת התמונה היא `images/direction-signpost.png` ושה־CSS נטען עם `?v=20261021-signpost-1`. גרסת ה־JavaScript העדכנית היא `?v=20261021-file-blocks-2`. אם התוכן מפסיק להיטען לאחר ההסרה, בדקו שב־`js/app.js` אין פניות ל־`#time-note` או ל־`#version`. אם האיור חתוך, בדקו את כללי `.hero-illustration` ואת `object-fit: contain`.

## טופס לקבוצה ללא הנחיות טקסט

1. רעננו את ממשק הסטודנט, בחרו קבוצה 3 ופתחו את השלב **היכרות והתנעה**. נכון לתיקון, הטופס שפורסם בשלב זה נקרא **בדיקה** וסוג המענה שלו אישי.
2. ודאו שהטופס מופיע בתוך **המרחב של קבוצה 3**, ושההודעה **אין הנחיות נוספות לקבוצה בשלב זה** אינה מופיעה באותו מרחב. ודאו שגם ההערה שהתחילה ב־**אם נדרש מספר קבוצה** הוסרה מליד הטופס.
3. פתחו את הטופס בתוך העמוד ובכרטיסייה חדשה. עברו לקבוצה אחרת; אם הטופס פתוח בתוך העמוד, אשרו את אזהרת המעבר רק לאחר שסיימתם את הבדיקה. ודאו שהטופס הפרטי לקבוצה 3 אינו מופיע לקבוצה האחרת.
4. בדקו גם בתצוגה המקדימה בעורך עם אותה קבוצה ואותו שלב. לפני רענון העורך שמרו את השינויים שטרם נשמרו.
5. בקבוצה ובשלב שאין להם הנחיות או טפסים משויכים, ודאו שהודעת היעדר התוכן עדיין מוצגת. טופס משותף לכל הקבוצות אינו מבטל הודעה על היעדר תוספות לקבוצה מסוימת.

צפוי: גם טופס לבדו נחשב לתוכן קבוצתי. אין הודעה סותרת על מרחב ריק לצד טופס משויך. טפסים משותפים נשארים מחוץ למרחב הקבוצה, ושיוך לשלב, שיוך לקבוצה וסימון לפרסום ממשיכים לסנן את התוכן. בדקו גם ברוחב 320 פיקסלים ובניווט מקלדת.

אם יש תקלה: רעננו את הדף ובדקו ש־`app.js`, `admin.js` וייבוא `helpers.js` משתמשים ב־`?v=20261021-file-blocks-2`. אם הטופס עצמו חסר, ודאו שבחרתם את השלב שאליו הוא משויך, שהשלב פתוח, שהקבוצה פעילה ושהטופס סומן ופורסם. אם הטופס מוצג אך ההודעה הסותרת נשארת, תעדו את כתובת הדף, הקבוצה והשלב כדי לבדוק אם נטען עותק ישן.

## הפעלת העורך והכניסה הראשונה

אפשר לפתוח גם את `admin.html` ב־Live Server כדי לערוך את עיצוב מסך הכניסה. לשמירה, העלאת PDF ופרסום נדרש שירות הניהול:

1. אם השירות אינו פועל, פתחו מסוף ב־VS Code בתיקיית `backend` והפעילו `npm.cmd start` או `./start.ps1`.
2. פתחו את [העורך המחובר](http://127.0.0.1:4173/admin.html), בדיוק בכתובת `127.0.0.1` ובפורט `4173`.
3. בהפעלה הראשונה בחרו סיסמה באורך 12 תווים לפחות, הקלידו אותה שוב ולחצו על שמירת הסיסמה וכניסה. אם כבר נבחרה סיסמה, התחברו עם `Admin` והסיסמה שנשמרה.

צפוי: בחירת הסיסמה מוצגת פעם אחת בלבד. לאחר כניסה מופיעים מסכי הניהול; במסך הקבוצות קיימות 35 קבוצות. פתיחת העורך ב־Live Server מציגה קישור לעורך המחובר.

אם יש תקלה: אם הדף אינו נפתח, בדקו שהשירות פועל. הודעת `EADDRINUSE` אומרת שכבר פועל שירות בפורט הזה; השתמשו בשירות הקיים או עצרו את ההפעלה הקודמת לפני התחלה נוספת. אם PowerShell חוסם את `start.ps1`, השתמשו ב־`npm.cmd start`. במקרה של אי־התאמה בין הסיסמאות או סיסמה קצרה, תקנו את השדות. אם הסיסמה כבר הוגדרה בלשונית אחרת, עברו למסך הכניסה. אין להוסיף סיסמה לקוד הציבורי ואין למחוק את מסד הנתונים כדי לאפס אותה.

## שמירת טיוטה, תצוגה מקדימה ופרסום

1. הורידו עותק של הטיוטה בכפתור **הורדת עותק העריכה** לפני בדיקת שינויים.
2. שנו טקסט בהנחיה קיימת, שמרו טיוטה ורעננו את העורך. ודאו שהטקסט נשמר.
3. פתחו את תצוגת הטיוטה המקדימה ואת אתר הסטודנטים בלשונית נוספת. הטיוטה אמורה לכלול את השינוי; האתר הציבורי אמור להמשיך להציג את הפרסום הקודם.
4. אם השינוי מתאים לפרסום, לחצו **פרסום הפעילות** ואשרו. בדקו את אתר הסטודנטים על השירות וגם ב־Live Server. רעננו או המתינו עד 30 שניות.
5. נסו קבוצות 1 ו־35, הנחיה משותפת והנחיה המשויכת לקבוצה אחת. ודאו שהשיוכים נכונים ושהשלבים נפתחים בהתאם למועדיהם.
6. אם בוצע שינוי זמני לצורך הבדיקה, החזירו את התוכן הרצוי, שמרו ופרסמו אותו.

צפוי: שמירה משפיעה רק על הטיוטה. פרסום מעדכן גם את `website/data/content.json` ואת קובצי ה־PDF הציבוריים, ללא פעולת ייצוא נוספת וללא שינוי HTML או CSS. כותרות שנערכו ישירות ב־HTML נשארות כפי שנכתבו ב־Live Server.

אם יש תקלה: שגיאות אימות מצביעות על השדות לתיקון; תקנו ושמרו שוב. אם החיבור פג, הורידו עותק עריכה לפני כניסה מחדש. אם מוצגת התנגשות בין לשוניות, שמרו עותק של השינויים המקומיים, טענו את הטיוטה העדכנית ושלבו מחדש את מה שצריך. אם הפרסום הצליח אך מופיעה אזהרת סנכרון ל־Live Server, ודאו שיש הרשאת כתיבה ומקום פנוי ב־`website/data`, ואז הפעילו `npm.cmd run export` מתוך `backend`. רעננו את אתר הסטודנטים. שינוי ידני ב־JSON יוחלף בפרסום הבא מהעורך.

## העלאת PDF כבלוק הנחיה נפרד

1. שמרו שינויים פתוחים לפני רענון העורך. לאחר עדכון השירות התחברו שוב, ועברו אל **הנחיות וקבצי PDF**.
2. העלו PDF קטן דרך **העלאת PDF כהנחיה נפרדת**. ודאו שנוצר בלוק **הנחיית קובץ** עם שם הקובץ, כפתור פתיחה וכפתור **מחיקת הקובץ**. בבלוק אין שדה טקסט, ובהנחיות טקסט אין יותר רשימת קבצים לצירוף.
3. העלו קובץ שני. ודאו שנוצר בלוק נוסף, ושהוא אינו מצורף לבלוק הראשון או להנחיית טקסט.
4. שנו לבלוק קובץ אחד כותרת, שיוך לשלב פתוח ושיוך לקבוצת בדיקה. סמנו אותו לפרסום, שמרו ובדקו במקדימה. פרסמו רק כאשר השינויים מוכנים להצגה.
5. בממשק הסטודנט בחרו את הקבוצה והשלב המתאימים. ודאו שהקובץ מוצג כבלוק נפרד, נפתח וניתן להורדה. אם לקבוצה יש רק קובץ ואין הנחיית טקסט, ההודעה **אין הנחיות נוספות לקבוצה בשלב זה** אינה אמורה להופיע.
6. עברו לקבוצה אחרת ולשלב אחר. קובץ המיועד לקבוצה אחת או לשלב אחד אינו אמור להופיע במרחבים האחרים. קובץ שטרם סומן ופורסם אמור להישאר בטיוטה בלבד.

צפוי: כל העלאה חדשה נשמרת בטיוטה כבלוק קובץ עצמאי, שאינו מסומן לפרסום כברירת מחדל. ניתן לקבוע לכל בלוק שלב, קבוצה, כותרת וסדר. קבצים שכבר הועלו לפני העדכון מוצגים גם הם כבלוקים; שמירת הטיוטה שומרת את ההפרדה. טקסט וקבצים שהיו יחד בהנחיה ישנה נפרדים לבלוקים עם אותם שיוכים ומצב פרסום, בלי למחוק את הטקסט.

אם יש תקלה: ודאו שהשירות המעודכן פועל, שהקובץ הוא PDF תקין בגודל עד 5MB ושהכתובת היא `127.0.0.1:4173`. אם הקובץ אינו מופיע לסטודנטים, בדקו את השיוכים, מועד הפתיחה וסימון הפרסום, ואז שמרו ופרסמו. אם רשימת הצירוף הישנה עדיין מופיעה, ודאו ש־`admin.js`, `helpers.js` ו־`domain.js` נטענים עם `?v=20261021-file-blocks-2`. בדקו במובייל ובמקלדת גם את פתיחת הקובץ והורדתו.

## הנחיות חדשות בראש רשימת המרצה

1. במסך **הנחיות וקבצי PDF**, לחצו על **הוספת הנחיית טקסט**. ודאו שהבלוק החדש מופיע ראשון וששדה הכותרת שלו מקבל מיקוד. הזינו כותרת וטקסט ושמרו.
2. העלו PDF. ודאו שבלוק הקובץ החדש מופיע לפני הנחיית הטקסט שהוספתם, וששדה הכותרת שלו מקבל מיקוד.
3. שנו את **סדר התצוגה** של אחד הבלוקים, שמרו ורעננו. הסדר בעורך צריך להישאר לפי מועד יצירת ההנחיה: החדש בראש. בדקו שהערך שערכתם ממשיך לקבוע את הסדר בתצוגת הסטודנטים ובמקדימה.

צפוי: הנחיות טקסט ובלוקי קבצים חדשים מוצגים מהחדש לישן גם לאחר שמירה וכניסה חוזרת. עריכת הנחיה קיימת אינה הופכת אותה להנחיה חדשה. רשומות ישנות שאין להן מועד יצירה מוצגות בהיפוך סדר ההוספה שנשמר, אחרי הרשומות החדשות.

אם יש תקלה: שמרו שינויים לפני רענון ובדקו שנטענת גרסת `20261021-file-blocks-2`. אם בלוק חדש עדיין מופיע בתחתית, ודאו ששירות הניהול עודכן וש־`admin.js` משתמש בפונקציה `newestInstructions`. אם סדר הסטודנטים שגוי, בדקו את ערכי **סדר התצוגה** עצמם; מועד היצירה אינו אמור לשנות אותם.

## מחיקת קובץ שהועלה

1. העלו קובץ בדיקה ולחצו בבלוק שלו על **מחיקת הקובץ**. בטלו את האישור תחילה; הקובץ והבלוק צריכים להישאר.
2. לחצו שוב ואשרו. ודאו שבלוק הקובץ הוסר, שהנחיות טקסט וקבצים אחרים נשארו, ושמסומן שיש שינויים שטרם נשמרו. שמרו טיוטה ורעננו; הקובץ אינו אמור לחזור.
3. אם מוחקים קובץ שכבר פורסם, ודאו ששמירה בלבד אינה משנה את הגרסה החיה. לאחר פרסום הקובץ אמור להיעלם מממשק הסטודנט. אם הוא היה התוכן היחיד של הקבוצה בשלב, הודעת היעדר התוכן חוזרת להופיע.
4. אם נדרש שחזור, טענו מההיסטוריה גרסה שבה הקובץ היה מפורסם. בדקו אותו במקדימה ופרסמו רק אם רוצים להחזירו לאתר.

צפוי: המחיקה מסירה את הקובץ ואת בלוקי ההנחיה שלו מהטיוטה. פרסום מחיל את ההסרה על ממשק הסטודנט. גרסאות קודמות והקבצים הנחוצים לשחזור נשמרים באחסון הפרטי.

אם יש תקלה: אם הקובץ חוזר אחרי רענון, ודאו ששמרתם את הטיוטה אחרי המחיקה. אם הוא עדיין מוצג לסטודנטים, ודאו שגם פרסמתם ורעננו את האתר. אם מתקבלת התנגשות גרסאות, גבו את העריכה, טענו גרסה עדכנית ובצעו את המחיקה שוב. אין למחוק ידנית את מסד הנתונים או קבצים פרטיים כדי לפתור את התקלה.

## קישורים ותאריכים בעורך

הוסיפו קישור וטופס תקינים ובדקו אותם במקדימה. לטופס משובץ השתמשו בקישור ההטמעה של Google Forms. הגדירו לשלב עתידי מועד קרוב ובדקו לפני המועד ואחריו; גוף השלב, הקבצים והטפסים אמורים להופיע רק לאחר הפתיחה. פרסמו רק אם התוכן והמועד מוכנים להצגה לסטודנטים.

אם יש תקלה: לקישור השתמשו בכתובת מלאה שמתחילה ב־`https://`. אם טופס אינו נטען, בדקו את הרשאותיו ואת קישור ההטמעה. אם שלב נעול בזמן שגוי, בדקו את השעה במכשיר ואת המועד שהוגדר בעורך.

## יציאה, הפעלה חוזרת ומקלדת

1. צאו מהעורך וודאו שנדרשת כניסה כדי להמשיך בעריכה.
2. לאחר שמירה, עצרו את השירות באמצעות Ctrl+C במסוף שבו הופעל והפעילו אותו שוב. התחברו עם אותה סיסמה.
3. עברו בעזרת Tab על שדות הכניסה, לשוניות הניהול וכפתורי השמירה והפרסום. בדקו גם חלון צר והגדלה של 200%.

צפוי: הטיוטה, הפרסום והסיסמה נשמרים אחרי הפעלה מחדש; החיבור הקודם מתבטל. המיקוד ברור והשדות והכפתורים נגישים במקלדת.

אם יש תקלה: ודאו שהשירות הופעל מאותו פרויקט ושלא הוחלפה תיקיית `backend/.local`. תקלה בפריסה או במיקוד יש לתעד עם רוחב החלון, הזום והפעולה שנכשלה. אל תנסו לפרסם שוב עד ששגיאת השמירה נפתרה.
